# Hanging indent for wrapped list items in the editor

Objective: when a list item, task or quote wraps in the editor, its continuation rows start under the item's text, not at column 0 (Vim's `breakindent`).
Branch: worktree `feat/explorer-crear-con-barra` (at `main` = `ed3bece`), delivered straight to `main` (owner's standing rule: no PR), without waiting for CI (L5); installed locally.
Test runner: `go test`, always `GOMAXPROCS=4 go test -p 2 -count=1 -timeout …` (60s test, 2m package, 5m suite). Forecast: about 300 authored lines.

## Specs

- S1 (L1): «cuando el texto hace salto de linea se pone debajo de -[] y asi y se ve feo». A wrapped line that starts with a list marker draws every continuation row indented to the column where the item's text starts. Markers: `- `, `* `, `+ `, `1. `, `1) `, each optionally followed by a task box `[ ] `, `[x] `, `[X] ` or `[-] `; and quotes `>` (with or without one space after), repeated (`> > `), optionally followed by a list marker (`> - [ ] `). Leading indentation counts, so a nested item (`  - …`) continues under its own text, not under its parent's (L3). The indent is the rune count of the matched prefix, a tab counting as 1, which is how the wrap draws it (V8). Detection is per line, without context: a list line inside a fenced code block or the front matter also gets it (V9, accepted: display only). `1) `, `[X]` and `[-]` go beyond the list offered in L2 (V15): same family, low risk.
- S2 (L2): Applies wherever the editor's raw text is drawn: the editor (`space r`), the split, and the raw block revealed in INSERT in the reading view (`space p`). The preview pane and the rendered rows of the reading view are not touched.
- S3: The indent is display only. The note's text is never changed, and copy, search, undo, `dd`, `o` and paste behave as before.
- S4: Cursor and mouse stay exact on indented rows (wide CJK runes excluded: clicks after them are already off at the baseline, V12): the drawn cursor, the terminal cursor and popups anchored to it (`CursorScreen`), `↑`/`↓`/`j`/`k` across wrapped rows keeping the screen column (counted from the text area's left edge, so indent cells count; a goal column inside a row's indent area lands on that segment's first character) (V14), mouse clicks and drag selection, wheel scroll, and the painted selection and syntax colours (every colour lands on the same character as without the indent).
- S5 (assumption A1): continuation rows are indented only when `indent <= m.width/2` (`m.width` = the text width, gutter excluded, as it is in live mode too); otherwise they wrap as today, so a deep marker never squeezes text into a thin column (V14).
- S6: Lines that are not list items or quotes wrap exactly as today. With the option off (nil), the textarea's output is byte-identical to today: `testdata/frames.golden`, `testdata/navigation.golden`, `view_ref_test.go`, `index_test.go` and `display_fuzz_test.go` pass untouched: `wrap(runes, width)` and `memoizedWrap(runes, width)` keep their signatures (V1). Content and app tests that wrap list lines may change only where the new indent is the reason, each change explained (V13).
- S7: README and CHANGELOG say what changed.

Assumptions:
- A1: the half-width threshold in S5 is the plan's choice, not the owner's. Checked by its test; changeable in one constant.
- A2: `[-]` counts as a task box because the preview already draws it (`internal/preview/look_test.go:15`).

## Design (from the read-only map, 2026-11-11)

- `internal/textarea` is the vendored bubbles v1.0.0 textarea; its only non-test user is `internal/content` (one `content.Model` for all three views). Add a nil-by-default field, e.g. `WrapIndent func(line []rune) int`, set in `content.New` (`internal/content/content.go:66`). Nil = today's behaviour (S6).
- Keep the invariant every caller relies on: the wrapped segments of a line have the same rune count as the buffer line plus one trailing space (V2; spaces are normalized to ' '). The indent never enters the wrap's output. A new `wrapIndent(runes, width, indent)` uses a per-row width (first row `width`, others `width - indent`) in all three width comparisons of today's `wrap` (textarea.go:1580, 1595 hard break, 1609 final), each measured against the row the word lands on; `wrap(runes, width)` stays as `wrapIndent(runes, width, 0)`, and `memoizedWrap` computes the indent itself (V1, V3); the indent is drawn in `View` (`textarea.go:1168`, wrapped-row loop at 1213-1271) after the line-number cell, with `style.Render`, outside `paint` (`extra.go:431-468`), and every width condition in that loop uses the row's width: the right padding, the trailing-space trim (`strwidth > m.width`, textarea.go:1247) and the past-end cursor check (`CharOffset >= m.width`, :1258) (V5).
- Column conversions add or subtract the indent on continuation rows (`RowOffset > 0` / segment `k > 0`): `LineInfo`/`wrapLineInfo` (`textarea.go:875-921`), `CursorUp`/`CursorDown` (`523-596`: `lastCharOffset` becomes a screen column, the fill loop subtracts the target row's indent and its `CharWidth-1` limit is measured in the same frame, V6), `ClickAt` only (`extra.go:121`: subtract the target row's indent from x, clamped at 0; `moveToVisual` itself stays a rune-offset function because `ScrollBy` passes `ColumnOffset`, extra.go:94, V4), `CursorScreen` (`extra.go:251-265`), the cursor cell in `View` (`1253-1265`).
- Caches: no key change. The indent depends only on the runes and the width, and the option is set once in `content.New` before any text, so the memo key (`index.go:79-88`) and the row-index key (`index.go:45`) stay valid. The field doc says it must be set before use (V7).
- Marker detection lives in `internal/content` (the highlight regexes are unexported, V8), one regex covering S1's combinations, modelled on `highlight.go:119-120`; `* * *` rules never wrap in practice and need no special case.
- `placeholderView` (`ansi.Wordwrap` at `textarea.go:1398`) only wraps the empty-note placeholder and is unaffected.
